# Internationalization (Planned)

Not yet implemented in this scaffold. Recommended approach when prioritized:

1. Adopt `next-intl` (works cleanly with the App Router) or Next.js's
   built-in i18n routing.
2. Priority languages, in order (confirm with AEC stakeholders):
   - English (default)
   - Urdu (RTL — plan CSS logical properties from the start; Tailwind's
     `rtl:`/`ltr:` variants help here)
   - Arabic (RTL — relevant given Quran/Arabic programs)
3. Extract all UI strings currently inline in components (Navbar, Footer,
   homepage sections, portal shells) into locale message files before this
   work starts — inline strings are acceptable for the scaffold stage only.
4. Keep RTL in mind in Tailwind config/layout: avoid hardcoded `left-`/
   `right-` utilities in favor of `start-`/`end-` logical equivalents.
5. Date/time formatting (timetables, invoices, attendance) should use
   locale-aware formatting (`Intl.DateTimeFormat`) rather than manual
   string building.
